# 🌿 CropDoctor — AI-Based Crop Disease Detection

> **SDG 2 — Zero Hunger** | Transfer Learning | MobileNetV2 | PyTorch | Streamlit

---

## Problem Statement

Crop diseases cause an estimated **20–40 % loss in global agricultural productivity** each year (FAO).  Small-scale farmers in developing regions are disproportionately affected because they lack access to agronomists or timely diagnostic tools.  Early, accurate identification of leaf diseases enables timely intervention, reducing crop losses and improving food security.

## Objectives

| # | Objective |
|---|-----------|
| 1 | Detect 12 common crop diseases (plus healthy classes) from a single leaf photo. |
| 2 | Deliver a lightweight model that runs on a standard CPU in under 2 seconds. |
| 3 | Provide practical, responsible treatment advice alongside each diagnosis. |
| 4 | Package the solution as a beginner-friendly web app accessible to farmers. |

---

## SDG 2 Relevance

CropDoctor contributes to **SDG 2 — Zero Hunger** by:

- Helping smallholder farmers detect disease *early*, before irreversible yield loss.
- Reducing over-reliance on chemical treatments through culturally appropriate, low-cost guidance.
- Running entirely offline (no cloud dependency after training), making it viable in low-connectivity areas.

## MobileNetV2 Transfer-Learning Approach

1. **Pretrained backbone**: MobileNetV2 trained on ImageNet 1000-class benchmark.
2. **Frozen feature extractor**: All convolutional layers are frozen initially — their ImageNet visual features transfer well to leaf images.
3. **New classification head**: The original `Linear(1280 → 1000)` is replaced with `Linear(1280 → N)` where *N* = number of selected disease classes.
4. **Head-only training** (~5–10 epochs): Only the new head weights are updated.  This is fast and prevents overfitting on a modest dataset.
5. **Optional fine-tuning**: After head convergence you can unfreeze the full network for a lower learning rate to squeeze extra accuracy.

## Data Preprocessing and Splitting

| Stage | Transform |
|-------|-----------|
| **Training** | Resize 224×224 → Random H-Flip → Random Rotation ±15° → Color Jitter → ToTensor → ImageNet Normalize |
| **Validation / Inference** | Resize 224×224 → ToTensor → ImageNet Normalize |

- **Split**: 80 % training / 20 % validation, **stratified** by class, seeded for reproducibility (`seed=42`).
- **No leakage**: train and val subsets are built from separate `Dataset` objects.
- The exact same split is reconstructed in `evaluate.py` so the val set is never seen during training.

## Setup Instructions (Windows PowerShell)

### 1 — Create and activate a virtual environment

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

> If you get an execution-policy error, run:
> `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser`

### 2 — Install dependencies

```powershell
pip install -r requirements.txt
```

> For GPU support with CUDA 11.8:
> ```powershell
> pip install torch torchvision --index-url https://download.pytorch.org/whl/cu118
> ```

### 3 — Download the PlantVillage dataset

1. Go to: <https://www.kaggle.com/datasets/emmarex/plantdisease>
2. Click **Download** (requires a free Kaggle account).
3. Unzip the archive.
4. Place the class folders inside `data/PlantVillage/` so the layout looks like:

```
data/
└── PlantVillage/
    ├── Tomato_Early_blight/
    │   ├── 001.jpg
    │   └── ...
    ├── Potato___healthy/
    └── ...
```

5. Verify the setup:

```powershell
python dataset.py --data_dir data/PlantVillage
```

### 4 — Train the model

```powershell
python train.py --data_dir data/PlantVillage --epochs 10 --batch_size 32
```

Expected output after each epoch:
```
Epoch 01/10 | Train Loss: 1.2345  Acc: 0.6100 | Val Loss: 0.9876  Acc: 0.7350 | Time: 45.2s
```

Saved artefacts:
- `models/best_model.pth` — checkpoint with the best validation accuracy
- `models/class_names.json`
- `outputs/training_curves.png`

### 5 — Evaluate the model

```powershell
python evaluate.py --data_dir data/PlantVillage
```

Saved outputs:
- `outputs/metrics.json`
- `outputs/classification_report.txt`
- `outputs/confusion_matrix.png`

### 6 — Launch the web app

```powershell
streamlit run app.py
```

The browser opens automatically at `http://localhost:8501`.

## Optional: LLM-Powered Advice (watsonx.ai or OpenAI)

Create a `.env` file in the project root (never commit this):

```dotenv
# IBM watsonx.ai
LLM_PROVIDER=watsonx
WATSONX_API_KEY=your_api_key_here
WATSONX_PROJECT_ID=your_project_id_here
WATSONX_URL=https://us-south.ml.cloud.ibm.com

# — OR — OpenAI-compatible
LLM_PROVIDER=openai
OPENAI_API_KEY=your_openai_key_here
```

If `LLM_PROVIDER` is not set or the API call fails, the app automatically falls back to the built-in local advice dictionary — **no functionality is lost**.

## Limitations and Ethical Considerations

| Limitation | Implication |
|------------|-------------|
| Trained on lab-quality images | May underperform on real field photos with clutter or unusual angles |
| 12-class scope | Does not cover all crop diseases; results for out-of-scope crops will be unreliable |
| No blur / OOD detection | Users should be informed to retake blurry photos |
| Confidence threshold (70 %) | Borderline cases are surfaced as low-confidence, not hidden |
| No personal data collection | Images are processed locally; no photos are sent to external services |
| Chemical advice is general | Specific doses and schedules are deliberately excluded to avoid harm |

**The tool is intended as a first-line screening aid, not a definitive diagnostic.  Farmers should always consult a qualified agronomist or agriculture extension officer before applying any treatment, especially chemical treatments.**
